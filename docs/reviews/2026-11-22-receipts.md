# Review: Phase 3.1 receipt details, search and PDF

- **Branch reviewed:** `feat/backend-receipts` (eee3053, fixes in ac37e54)
- **Reviewer:** independent review agent (Opus 5.5), read-only
- **Integration check:** Sonnet 5.5, over real HTTP
- **Date:** 2026-11-22

## Scope

- `GET /receipts` (search)
- `GET /receipts/{id}`
- `POST /receipts/{id}/print`, which returns an A5 PDF made with fpdf2
- amounts in words, Indian style
- centre-detail settings
- the `ix_receipts_issued_at` migration

## Findings

| ID | Severity | Finding | Outcome |
|---|---|---|---|
| H1 | High | Printing was a `GET` that counted copies. A reload, a prefetch or a link from another site (SameSite=Lax cookies) could use up the original, so the customer's first real print would say DUPLICATE. | **Fixed.** Printing is `POST /receipts/{id}/print`, which needs the CSRF token. `GET` returns 405, and the never-released `GET /pdf` route is removed. |
| M1 | Medium | Long names, descriptions and references overflowed the page or overlapped the amounts. | **Fixed.** Rows now wrap in two columns. Checked on a rendered sample. |
| M2 | Medium | A wrong `RECEIPT_FONT_PATH` made every print fail with 500. | **Fixed.** Printing falls back to Helvetica and logs a warning. Joined letters in Indic scripts still need a shaping library; this is documented as a later option. |
| M3 | Medium | The DUPLICATE and CANCELLED marks appeared on page 1 only. | **Fixed.** A page header repeats the receipt number and the marks. The reason is shortened to 300 characters on paper. |
| L1 | Low | Writing a negative amount in words crashed. | **Fixed.** It now raises a clear `ValueError`. |
| L2 | Low | Strict enums in the snapshot could break old receipts. | **Fixed.** The snapshot stores plain strings, and the list reads the name safely. |
| L3 | Low | Search used the current customer name but showed the printed one. | **Fixed.** Search matches both. |
| L4 | Low | A print is counted even if the response never reaches the user. | **Accepted.** An explicit print action makes this rare. |
| L5 | Low | Performance: lists sorted without an index, and the date filter could not use one. | **Fixed.** New `issued_at` index, and dates are compared as instants at Asia/Kolkata midnight. Text-search and font caching are deferred to scale. |
| L6 | Low | The PDF response had no schema. | **Fixed.** Documented as `application/pdf` binary. |
| L7 | Low | Test gaps. | **Added:** CSRF and GET refusal, long text, multi-page marks, a missing font, old snapshots, the midnight boundary, and filters on other people's jobs. |

## Integration check (real HTTP)

All 7 steps passed:

1. Payments created receipts `RCP-2026-000001` and `-000002`.
2. The receipt detail showed the snapshot with a masked phone and the amount in words.
3. Printing:
   - The first print is the original, and the second says DUPLICATE COPY.
   - `GET /print` returns 405, and a print without CSRF returns 403 without counting.
   - `GET /pdf` returns 404.
4. A voided payment's receipt prints CANCELLED with the reason.
5. Search, filters and pages work. An employee not assigned to the job sees nothing (404 or empty).
6. Audit rows record copies 1 and 2 with the duplicate flag, and hold no phone or reference.
7. The contract change is additions only, with the PDF documented as binary.

The integration agent also noted that the job response shows the customer's full phone to the assigned employee. This is intended: staff call customers. Masking rules cover Aadhaar, PAN, chassis and engine numbers, and receipts and lists mask the phone.

## Checked and found sound

- **Access:** employees see only receipts of jobs they are assigned to. Filters only narrow within that, and anything else is 404.
- **Print counter:** a row lock means two simultaneous prints can't both be the original. A failed render is not counted.
- **Headers:** `Content-Disposition` uses the server-made receipt number, so headers can't be injected.
- **Text in the PDF:** user text is escaped safely for the built-in font.
- **Dependencies:** fpdf2 2.9.0, fonttools and pillow are pinned in `uv.lock`.

## Checks

- **Full suite:** `scripts/check.sh backend` gives 553 passed, with the contract in sync on the owner branch.
- **Deliberate breaks:** the tests caught 15 of 15, covering the access rules, the duplicate marking, the print count, the cancelled mark, LIKE escaping, the date range and each review fix. One of these was first missed; that test was strengthened.
